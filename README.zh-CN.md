# Agent Task Gate

[English](README.md)

Agent Task Gate 用于在合成任务、示范轨迹和验证器进入智能体训练集或评测集之前进行审查。它把候选批次整理为证据台账、环境与验证器门禁矩阵、逐样本结论、批次风险、修复项和有序的下一步检查。

## 解决的问题与目标用户

看起来合理的生成式提示词并不一定是合格训练数据。任务可能引用不存在的工具、要求策略禁止的状态变更、使用会接受错误终态的验证器、重复已有种子，或对目标模型过于简单。这些缺陷会奖励不安全或无效的行为。

本 Skill 面向智能体训练团队、评测工程师、数据集整理人员、应用研究人员，以及需要在接收合成样本前形成一致审查交接的人员。

## 适用场景

- 审查由模型失败或能力卡生成的候选任务。
- 审计带验证器的 SFT 或强化学习样本。
- 把混合批次分流到接受、修复、拒绝和未验证队列。
- 检查参考轨迹能否在声明的工具环境中执行。
- 识别会接受错误目标、部分完成或禁止副作用的验证器。
- 记录缺失的相似度、谱系、覆盖范围和接收率证据。

## 已实现功能

- 四类证据：`observed`、`derived`、`claim`、`unknown`。
- 四种受限结论：`accept`、`repair`、`reject`、`unverified`。
- 相互独立的可行性、真实性和难度门禁。
- 基于环境契约的工具、状态变更、策略和实体检查。
- 正向回放与实质不同的负向验证审查。
- 验证器一致性、健全性与完备性检查。
- 来源与评测数据泄漏审查。
- 批次覆盖、重复、谱系、产出率和反复失败模式分析。
- 可验证的修复项，以及能够改变结论的最小下一步检查。

## 完整流程

1. 导出环境契约、系统规范、提示词、初始状态、参考轨迹、验证器和已有日志。
2. 在可用时补充目标模型/教师模型试验、来源与谱系记录、相似度结果和批次数量。
3. 要求智能体使用 **Agent Task Gate**；如果本次仅做只读审查，明确禁止执行环境动作。
4. 在采用结论前，先检查证据台账和环境契约。
5. 将通过样本送往后续流程，将可修复样本连同必需检查退回，移除拒绝样本，并为未验证样本补齐证据。
6. 对修改后的候选重新审查；旧结论不能自动沿用到新内容。

## 环境要求

- 使用已测试安装包格式时，需要 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork) 0.50.12 或更高版本。
- 已测试的桌面流程使用本地 iPolloWork 项目和 OpenCode 引擎。
- 候选任务可采用 Markdown、JSON、YAML 或粘贴文本。
- 纯文档审查不需要 API Key、训练框架、外部账号或环境连接。

本 Skill 不会回放动作、调用训练基础设施、生成数据集，也不能证明模型一定会提升。

## 输入与输出

### 输入

- 环境版本、工具、状态、状态变更和策略；
- 候选 ID、系统指令、用户提示和初始状态；
- 能力目标、参考轨迹和期望终态；
- 验证器逻辑或成功条件；
- 正向与负向验证证据；
- 求解试验与难度策略；
- 来源、许可证、谱系、相似度、覆盖范围和批次数量。

### 输出

一份包含十个固定章节的 Markdown 审计：范围、证据台账、环境契约、候选门禁矩阵、批次结论、逐候选结论、覆盖与批次风险、必需修复、下一步检查、训练使用边界。

## 端到端示例（End-to-end example）

使用 [examples/candidate-batch.md](examples/candidate-batch.md)。它包含三个帮助台任务：

```text
使用 Agent Task Gate 审查 examples/candidate-batch.md。不要执行工具或训练。保留所有标识和计数，并保存完整 Markdown 审计。
```

预期行为：

- 候选 A 为 `repair`，因为验证器会接受错误的优先级幅度。
- 候选 B 为 `reject`，因为核心工具不存在。
- 候选 C 为 `unverified`：尽管现有正向与负向检查通过，但完备性以及相似度/谱系证据仍未知。
- 批次结论为 `unverified`，并给出验证器、可行性、相似度、谱系和产出率检查顺序。

参见 [examples/expected-audit.md](examples/expected-audit.md) 和桌面端生成的 [docs/ipollowork-acceptance-output.md](docs/ipollowork-acceptance-output.md)。

## 在 iPolloWork 中使用

1. 从 GitHub Release 下载 `agent-task-gate-1.0.0.ipollowork-plugin`。
2. 在 iPolloWork 打开 **扩展 → 插件 → 添加 → 文件**。
3. 选择安装包，确认发布者为 `Sevaschan`、版本为 `1.0.0`、包含一个 Skill 资源。
4. 安装后启用插件和 **Agent Task Gate** Skill。
5. 打开本地 OpenCode 项目并添加或粘贴候选批次。
6. 明确要求智能体使用 Agent Task Gate，并确认它读取 `SKILL.md`、`quality-gates.md` 和 `audit-format.md`。
7. 检查并导出生成的 Markdown 审计。

如需独立 Skill 导入，请解压 `agent-task-gate-1.0.0-skill.zip`，在 **导入本地 Skill** 中选择其中直接包含 `SKILL.md` 的 `agent-task-gate` 文件夹。GitHub URL 不是通用安装方式。

## 常见问题（FAQ）

### Skill 会执行候选任务吗？

不会。它只审查提供的证据。只有用户提供了回放日志，该日志才能作为观察证据。

### 成功的参考回放足以接受验证器吗？

不足。相关错误结果也必须失败，且验证器应允许合法的替代解法。

### 每个数据集都必须使用相同的目标/教师成功率阈值吗？

不需要。Skill 会记录用户提供的难度策略并检查可比性，不会强制统一阈值。

### `unverified` 样本可以修复吗？

通常可以，但必须先补齐缺失证据。该结论用于避免把证据缺失错误地当作内容缺陷。
